# 验证记录与验收方法

[项目主页](../README.md) · **简体中文** · [English](./validation.en.md) · [协作与运维](./operations.md)

源码测试、运行时加载和真实 Slack 行为分别验证。下面的实测记录只描述当时的指定部署，不是所有账号、版本或对端组合的兼容性承诺。

## 分层验收

| 层级 | 需要的证据 | 不能替代它的结果 |
|---|---|---|
| 1. 收发通路 | 一条真实入站、实际处理及正确目的地回发 | 进程启动、connected 日志、能读历史或离线测试 |
| 2. 真实 agent | 实际模型 / agent 调用，能结合任务与限制回答 | echo、固定模板或“已读上下文”的自述 |
| 3. 双向协作 | 分别记录 A→B 与 B→A 的触发、上下文、回复位置与次数 | 单方向成功、一对通过推断所有对端、代码合并 |
| 4. 自然多轮 | 一条开放任务，自主提问、审查与修订，形成共同结果并停止无意义循环 | 固定接力、各说一条、人工催答或代答 |

先在用户授权范围内验证一对 agent，再扩展参与者。配对初检在 A→B、B→A 各发送一次独立探针，各最多回复一次；随后另做自然多轮测试。每轮使用新的测试标记，分清顶层与线程任务；发送结果不明时先查证，不通过重复发送寻找成功。

## 已知边界

- **历史不确定项仍保留。** 一条旧 Muse 发送的正文可见，但缺少能严格关联到该尝试的回执。它保持 `uncertain`，没有手工 ACK、清状态或重发；新路径通过不追溯确认旧记录。
- **响应不是实时保证。** 事件调度、外部 agent 唤醒、模型和代理网络都会影响表现；本次测试未证明任意并发任务都能收敛。
- **故障证据分层。** 真实网络断连、断电、重投递和长期运行没有全部在线注入验证；已有隔离故障测试不能覆盖每一种生产故障。
- **平台能力不同。** Hermes 补丁须匹配上游版本；DOTS 消息事件能力依赖账号与组织策略。DOTS reference 的离线去重实现没有部署进托管运行时，不能证明它具备 exactly-once。
- **合并不等于生效。** 部署需检查代码、有效配置、真实 hook / gateway 加载，并重新验证目标频道与对端。新安装不会自动继承维护者的私有配置。
